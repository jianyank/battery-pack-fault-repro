## 2. 本项目复现了什么

```
原始 .mat → 通道切分 → 归一化(训练折拟合)
        → 非对称卷积自编码器（编码器按 Table 1；变分头；三项损失）
        → 24 维故障指标（物理电压域）
        → LOF + 0.99 分位阈值 + 持久性
        → 检测对照表 + 图表
```

产物（`outputs/<timestamp>_<tag>/`）：

| 文件 | 内容 |
|---|---|
| `model_*/history.csv` | 逐 epoch 的 train/val 的 total、**recon、late、reg 三分量** |
| `model_*/best.pt` | 最佳 checkpoint（含归一化统计量，供反归一化） |
| `lof_scores_<dataset>_pack<id>.csv` | 逐窗 LOF 分数、阈值、是否确认 |
| `detection_table.csv` | 各数据集的越限率、K=1/K=5 确认率、首次报警位置 |
| `figures/*.png` | 训练历史、LOF 分数曲线、越限柱状图 |
| `summary.json` | 全部结果 + `assumed` 清单快照 + 时间轴状态 |

**自检**：`python scripts/smoke.py` 共 10 项，含"LOF 校准集分数中位数应 ≈ 1"这一
独立正确性佐证（实测 **1.039**）。

## 3. 论文主张 vs 可复现性

| 论文主张 | 可复现性 | 原因 |
|---|---|---|
| 训练链路（三项损失、非对称结构） | ✅ 已实现 | 论文给了结构；未给项已显式假定 |
| 24 维故障指标 | ✅ 已实现 | §2.3 给了完整公式 |
| LOF 检测 + 0.99 分位阈值 | ✅ 已实现 | §2.4 给了完整公式 |
| 重建保真度 | ⚠️ 可对照但**口径不同** | 见下方说明 |
| 「最早/并列最早报警、提前量数日至 200 天以上」 | ❌ 不可复现 | 天数以**投运日**为零点，本地无投运日期；且 `ThisTimeSlot` 是不可读的 MCOS 对象，窗口序号不是时间轴 |
| 「未见包上保持低虚警率」 | ❌ 不可验证 | 无独立健康段，无法定义虚警率 |
| 单体级定位（Table 5） | ❌ 不可验证 | `Hiddall` 与对齐目标**同源**，非独立真值 |
| Table 4 的 pack **12、14** | ❌ 无数据 | 本地只有 14 个包，不含 12、14 |
| Table 1 的解码器结构 | ❌ 无法照抄 | 论文 Table 1 与 Table 2 **自相矛盾**（推算得 746×8，声明 256×8），见 `DEVIATIONS.md` C1 |

### 关于重建保真度的对照

本项目报 `val_recon`（对**稳健标准化后**电压的 MSE）。若要与论文基线数值比较，
必须先确认三个口径一致：**归一化方式**（论文未提）、**选权判据**（论文未提）、
**MSE 是"按样本求和"还是"按元素平均"**（论文式 (2) 是求和，本项目是平均，差常数因子 256×8）。
三者不一致时，数值不可直接比。本项目**不主张**与论文的重建数值可比。

## 4. 两个协议 —— 最容易误读的地方

论文 §4.1 的协议是：用 `6/8/9/10` 的**正常段**训练，在**同样这四个包**的故障段上检测。
被检包的正常工况**模型见过**，所以曲线呈"一条平线 + 一个尖峰"。

跨包留出（LOPO）是**另一个协议**：每次只用另外三个包训练，在被留出包上检测。
被检包工况模型**没见过**，正常段重建变差、LOF 整体抬高，越限比例会远高于 1%。

> **"图上看起来全是故障"通常就是把 LOPO 的结果当成论文协议的结果来读。**
> LOF 的符号约定与实现已由自检验证（校准集分数中位数 ≈ 1），该现象与"算错"无关。

本项目 `run_all.py` 的 `--protocol` 参数显式选择，所有图标题都标注所用协议。

### 实测：协议造成的差异（同一批数据、同一份 LOF 实现）

对**同一批**"该电池包自身的窗口"（`StandTrainData.mat` 中该包的窗）评分，只换协议：

| 包 | `paper` 协议越限率 | `lopo` 协议越限率 | 倍数 |
|---|---:|---:|---:|
| 6 | 0.32% | 32.48% | ~100× |
| 8 | 1.68% | 63.00% | ~37× |
| 9 | 0.59% | 19.65% | ~33× |
| 10 | 1.75% | 32.69% | ~19× |

**越限率差 19–100 倍，而 LOF 的实现一行没改。** 差异全部来自"被评包的工况模型见没见过"。

### 实测：故障段 vs 正常段的区分度（`paper` 协议）

| 数据集 | 中位 LOF | 越限率 (K=1) | 确认率 (K=5) |
|---|---:|---:|---:|
| `train`（正常段，模型见过） | ~1.03–1.06 | 0.32–1.75% | 0% |
| `test1`（**同样四包的故障段**） | 1.4–2.4 | **45.2–75.2%** | **24.3–50.8%** |

故障段的 LOF 中位数整体抬高、且**连续越限成段**（最长连续越限最高达 125 个窗，占该序列 20.9%）。
**这是清晰的检测信号**：在论文协议下，故障段"大多越过阈值线"是**正确检出**，
而不是"全是故障"的错误。判读这类图时，**必须先确认画的是正常段还是故障段**。

`θ` 实测为 1.52（`paper`）/ 1.44–1.57（`lopo` 各折），与论文 §4.3 报告的
4.17 / 4.58 同量级但更低 —— 阈值依赖归一化方式与 k，**数值不可直接比**（见 `DEVIATIONS.md` A11/A12）。

### 阈值跨域失效的机理

论文取训练集 LOF 分数的 99 分位作阈值 ⇒ **训练数据本身就有约 1% 窗口越限**。
被评窗口若来自另一分布，越限比例必然显著高于 1%。因此 `detection_table.csv` 中
**同时记录校准集分数的中位数与 p99**，供判断阈值是否发生了跨域迁移：
若校准中位数已明显偏离 1，说明正常工况本身就散布在多个密度区域，阈值的迁移能力必然很弱。
